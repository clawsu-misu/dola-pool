# 怎么获取 dola 账号的 Cookie

号池用 Cookie 导入的号走「纯 API」出片：不开浏览器，最稳定，**30 秒两段拼接也只能用这种号**。
这篇教你把浏览器里已经登录的 dola 账号导出成 Cookie，粘贴到管理面板。

> ⚠️ Cookie 就是账号的登录凭证，拿到它就等于登录了你的账号。**不要发到群里、不要截图外传**。

---

## 先知道三件事

1. **关键是 `sessionid`**。导出来的内容里必须有 `sessionid=...` 这一项，号池就是靠它认号、去重的。
   没有 `sessionid` = 没登录 / 导错了网站。
2. **一个号一份 Cookie**。要导多个号，每个号在**单独的浏览器窗口**里登录（见下方「导多个号」）。
3. **导出后不要点「退出登录」**。退出会让这份 Cookie 当场作废，号池里的号也跟着失效。用完直接关窗口就行。

---

## 方法 1：Cookie-Editor 插件（最简单，推荐）

1. Chrome / Edge 应用商店搜索安装 **Cookie-Editor** 扩展（作者 cgagnier）。
2. 打开 <https://www.dola.com>，登录你的 dola 账号，确认已经进到**聊天页面**（能看到对话框）。
3. 点浏览器右上角的 Cookie-Editor 图标 → 点 **Export** → 选 **Header String**（头文本格式）。
   内容会自动复制到剪贴板，长这样（很长的一行）：
   ```
   passport_csrf_token=xxx; sid_guard=xxx; sessionid=xxxxxxxx; sid_tt=xxx; ...
   ```
4. 打开号池管理面板 → 「账号管理」→「**＋ 批量添加**」→ 选「**Cookie 头文本**」标签。
5. 把刚复制的内容粘贴进文本框，**一个账号一行**；多个账号就换行接着粘贴。然后点【开始导入】。

> 也可以在第 3 步选 **JSON**：导出的是 `[ {...}, {...} ]` 数组，同样粘到「Cookie 头文本」框里，
> 一个数组一个账号，多个数组可以连着粘。单个号也可以用「＋ 添加账号」→「Cookie 导入」标签粘 JSON。

---

## 方法 2：不装插件，用浏览器开发者工具

1. 打开 <https://www.dola.com> 并登录，进到聊天页面。
2. 按 **F12** 打开开发者工具 → 切到 **Network（网络）** 标签。
3. 按 **F5** 刷新页面，在请求列表最上面点第一条（名称一般是 `www.dola.com` 或 `chat`）。
4. 右侧 **Headers（标头）** → 往下找到 **Request Headers（请求标头）** 里的 **`cookie:`** 这一行。
5. 在它的值上右键 → **Copy value（复制值）**（或者手动选中整段复制）。
6. 粘贴到面板「Cookie 头文本」框里，一行一个号。

> ❌ **不要**在控制台里用 `document.cookie` 取：`sessionid` 是 HttpOnly 的，`document.cookie` 取不到它，
> 导进去的号是无效的。

---

## 方法 3：本地登录工具 `tools/login.py`（登录要走代理 / 号池在服务器上）

方法 1、2 要求浏览器能直接登进 dola。号池部署在服务器上（没显示器、登录加号用不了），或者登录要走代理
（例如 1024Proxy）时，用仓库自带的本地工具：**在你自己的电脑上开浏览器、手动登录，工具只负责抓 Cookie
并送到服务器**。Google / Apple / 手机号任意登录方式都行，滑块直接用手拖。

```bash
cd dola-pool
pip install -r requirements-dev.txt
python -m patchright install chromium        # 浏览器内核

python tools/login.py --web                  # 网页界面（推荐）：自动打开 http://127.0.0.1:<端口>/?token=...
```

1. 页面里填账号名和代理（1024 账密 / 1024 API 提取 / 自定义代理地址 / 本机号池里绑定的），点「开始登录」。工具先探测
   代理出口——**必须是日本 / 韩国**，连不上就停、不打开浏览器，否则 dola 会拒绝访问。
2. 这台电脑弹出浏览器窗口，在里面手动登录（登进 dola 即可），进度实时显示在页面上；关掉窗口 = 取消。
3. 检测到 `sessionid` 后自动收尾，页面变绿：
   - Cookie 导出到 `accounts/<账号名>/cookies-export.json`（已 gitignore，不要外传）；
   - 同时复制到剪贴板：到服务器面板「＋ 批量添加 → Cookie 头文本」直接粘贴。多个号的导出包可以连着粘，
     按 `sessionid` 自动去重、自动命名 accN；单个号也可以用「＋ 添加账号 → Cookie 导入」；
   - 想省掉手动粘贴，在页面下方填服务器面板地址和管理员账号，点「推送」：工具会等服务器导入并**在线验证**
     结束才报结果。接着登下一个号：改账号名再点「开始登录」。
4. 导入后照常「你好探测」，通过后开始接单。

不想开页面用命令行，效果相同：

```bash
# 走 1024Proxy 账密隧道（网关地址、密码在 1024 控制台「账密认证 → 去使用」查看）
python tools/login.py acc1 --p1024-user <账号> --p1024-gateway <host:port>

# 或任意代理
python tools/login.py acc1 --proxy http://user:pass@host:port

# 直推服务器（可选；不加则只导出文件 + 复制到剪贴板）
python tools/login.py acc1 --p1024-user <账号> --p1024-gateway <host:port> \
    --server https://你的面板地址 --server-user 管理员用户名 --proxy-id <服务器上的代理 ID>
```

说明：

- **网页界面只监听本机**（127.0.0.1），地址带随机 token：别的网页、局域网都调不动；Cookie 值只写导出文件，
  不经过页面。页面没自动打开时，把终端里打印的完整地址粘到浏览器；回到终端按 Ctrl+C 结束。
- **1024 在网页上有两种，都按控制台原样，工具不拼接**：账密把 curl 的 `-x`（网关）和 `-U`（用户名:密码）分三段填入，用户名里的地区在控制台选 JP 或 KR，不要用 Rand；API 提取粘贴控制台生成的链接（`white.1024proxy.com/white/api?region=JP…`，txt 或 json 都行）。这种链接走白名单：页面会检测这台电脑的公网 IP，点「复制」后到 1024 控制台白名单里添加。加的是本机 IP，不是代理的日本出口。提取结果只有地址、没有协议，工具会连上去认：1024 白名单节点是 SOCKS5，按 HTTP 去连会被对端直接断开。认完再探测出口，连不上就停，不打开浏览器。
- **命令行仍可自动拼用户名**：`--p1024-user` 给短账号时，按官方格式拼 `-region-JP-sid-…-t-120`（`--p1024-region` / `--p1024-session` / `--p1024-ttl`）。控制台已经拼好的完整用户名（`…-region-JP-sid-…-t-10`）原样使用，不再套一层，否则网关会直接断开。网页没有地区、会话、时长这几栏，地区写在你粘贴的用户名或 API 链接里。服务器那边也要给这个号绑日本 / 韩国代理（直推用 `--proxy-id`，粘贴导入的在面板里绑）。
- **密码不用写在命令行**：网页里填表单（推送完自动清空密码框，不保存）；命令行读环境变量 `DOLA_P1024_PASS`、
  `DOLA_ADMIN_PASSWORD`，都没有则交互输入。
- **会话过期后续期**：网页勾「从零登录」（命令行加 `--fresh`）清掉本地旧 profile 重新登录，再导一次。直推会提示
  「账号已存在」——先在服务器上删除同名旧号再重推。
- 导入的号没有保存登录凭据，会话失效后无法自动重登，重跑一次本工具即可。
- `--help` 看全部选项。豆包号见下文「豆包（doubao.com）的号」。

---

## 导多个号

每个号需要一个**互不干扰的浏览器会话**，任选一种：

- **浏览器多用户（推荐）**：Chrome 右上角头像 →「添加」新建一个用户，每个用户登录一个 dola 号。
  Cookie-Editor 需要在每个用户里各装一次。
- **无痕窗口**：每开一个无痕窗口登录一个号、导出后**直接关窗口**（不要点退出登录）。
  注意：同时开着的多个无痕窗口是共享 Cookie 的，必须**导完一个、关掉、再开下一个**。

---

## 导入之后

1. 导入结果里：`✓ 已创建：acc13、acc14` = 新建成功（自动命名 accN）；`↻ 已存在(sessionid 重复)` = 这个号已经导过了，没有重复建号。
2. 给新号**绑定代理**（日本 / 韩国出口），账号行里点「代理(默认)」按钮。
   多个号尽量分到**不同出口 IP**：同一出口的号越多，越容易被 dola 判「访问频繁」(710022002)。
3. 点「**你好探测**」：通过后号从【待激活】进【满额】，开始接单。
   探测会真的发一句「你好」，正常要几秒、能看到回复字数。

## 豆包（doubao.com）的号

号池也能放豆包号（接 `doubao-seedance-*` 模型，见 README「豆包号的模型」）。导法和上面一样，只是换个网站：

1. 在 **www.doubao.com** 登录（国内手机号），用方法 1 或方法 2 导出 Cookie。
2. 粘贴到「批量添加 → Cookie 头 / JSON」：
   - **Cookie JSON**（Cookie-Editor 导出）自带域名，号池自动认出是豆包号；
   - **Cookie 头**（一行 `a=b; c=d`）不带域名，粘贴前把下面的「站点」选成「豆包 doubao.com」。
3. 导入后账号「来源」列显示蓝色的「豆包」。豆包号**不需要绑日本 / 韩国代理**，境外服务器直连就能用。
4. 豆包号的「你好探测」只查登录态（不发消息、不花额度），通过后进【满额】开始接单。
5. 第一次接会员模型（2.0 / 2.5）时，号池会自动认出它是「会员」还是「免费号」并记在「来源」列下面。
6. 豆包默认给视频加「豆包AI生成」明水印（按号设置）。号池探测时会自动替号关掉（`DOUBAO_AUTO_NO_WATERMARK=1`），
   「来源」列下显示「无水印 ✓」；显示「⚠ 未关水印」时点一下「你好探测」，或到豆包设置 → AI 生成水印管理里手动关。

同样**不要在浏览器里点退出登录**：实测在浏览器退出豆包后，号池里那份 Cookie 立刻提示「登录已过期」。
换号登录请用无痕窗口或另一个浏览器。

## 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 导入结果显示「未导入任何账号」 | 复制的内容里没有 `sessionid`，或者复制的不是 dola.com 的 Cookie。确认在 dola.com 页面导出、已经登录。 |
| 「你好探测」判被登出 / 进【风控】 | Cookie 已失效：在浏览器里点过退出登录、改过密码，或者导出太久。重新登录导出一份，删掉旧号再导。 |
| 探测报「访问频繁」(710022002) | 不是 Cookie 的问题，是出口 IP 被限流。换一个不同 IP 的代理，或等一会儿再探测。 |
| 导入后号一直在【待激活】 | 还没探测过。绑好代理后点「你好探测」或顶部「你好探测」批量探测。 |
| 本地登录工具提示「出口不是日本/韩国」 | 代理地区不对。网页把控制台用户名或 API 链接里的地区改成 `JP` / `KR` 后重跑；命令行短账号用 `--p1024-region`。 |
| 本地登录工具提示「代理不可用，已停止」 | 网关连不上，或把 HTTP 当成了 SOCKS5（反过来也一样）。API 提取由工具认协议；账密隧道按控制台 curl 原样填 `-x` 和 `-U`，不要再手拼一层。 |
| 本地登录工具直推提示「账号已存在」 | 服务器上有同名账号。续期先在服务器上删除旧号，再从零登录（网页勾「从零登录」，命令行 `--fresh`）重推。 |
